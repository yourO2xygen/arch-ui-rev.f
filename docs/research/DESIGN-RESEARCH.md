## 2. Метрики иконок: постоянный эффективный штрих

### 2.1 Проблема

Lucide нарисован в viewBox 24 со stroke = 2, т.е. «родной» вес штриха = 2/24 ≈ 8.3%
от размера глифа. Если рисовать path «как есть» в 14px, штрих станет 2 × 14/24 =
**1.17px** — иконка в шапке панели будет заметно тоньше той же иконки в тосте
(32px → 2.67px). В монохромном UI, где вес линии — единственный носитель стиля,
это недопустимо.

### 2.2 Правило (рекомендация)

> **Effective stroke E = 1.5px — постоянный физический штрих для всех иконок
> во всех контекстах.**
>
> ```
> strokeWidth(viewBox) = E × 24 / size        (если рисуем path в координатах 24)
> scale                = size / 24            (если рисуем в px контекста)
> strokeWidth(px)      = E                    (константа при любом размере)
> ```

В QML (Canvas): `ctx.scale(s, s); ctx.lineWidth = E / s;` — рендер всегда 1.5px.
В `Shape`+`ShapePath`: масштабировать координаты, `strokeWidth: 1.5`.

Почему 1.5, а не 2 или 1.75:
- **E = 2** при 12–14px даёт штрих = 16–17% глифа: мелкие детали (пины `cpu`,
  точки `bluetooth`, `r=2`-кружки) сливаются, иконка выглядит «жирнее» текста
  11px рядом. Отвергнуто.
- **E = 1.75** — компромисс без преимущества: на чёрном фоне при 14px уже тяжеловато,
  при 32px разница с 1.5 незаметна. Держать как **fallback**, если после первой
  сборки тонкие иконки покажутся слабыми на пёстрых обоях (максимум в одном
  токене `E_ICON`).
- **E = 1.5** при scale 1.2 = **1.8 физических px** — попадает в «толстую» зону
  антиалиасинга, выглядит собранно. Штрих 1.5px чуть тяжелее стемма текста 11px
  (~1px) — правильный оптический приоритет иконки над подписью.

### 2.3 Таблица «контекст → размер → масштаб → stroke в координатах 24»

| Контекст | size, px | scale = size/24 | strokeWidth (vb) = 36/size | где в UI |
|---|---|---|---|---|
| Иконка в head панели | 14 | 0.583 | **2.57** | все панели, `▸ TITLE` |
| Инлайн-иконка в строке/мета | 12 | 0.5 | **3.00** | docker-тулбар, foot |
| Чип с иконкой | 12 | 0.5 | **3.00** | чипы состояния, табы |
| Иконка кнопки h26 | 14 | 0.583 | **2.57** | kill, start/stop/restart |
| Иконка в поле ввода | 16 | 0.667 | **2.25** | launcher dock, chat send |
| Плитка-инициал / строка списка | 16 | 0.667 | **2.25** | launcher rows, aimgr |
| Иконка-плитка уведомления | 24 | 1.0 | **1.50** | notifcenter rows |
| Иконка-плитка тоста | 32 | 1.333 | **1.13** (min 1.25 → 1.67*) | toasts |
| Плитка logout | 20 | 0.833 | **1.80** | 5 плиток сессии |
| Иконка вкладки/табов | 14 | 0.583 | **2.57** | Logs/Resources/Ports, Active/History |
| Мета-иконка в foot | 12 | 0.5 | **3.00** | счётчики, подсказки |

\* правило пола: `strokeWidth(vb) = max(36/size, 1.25)` — ниже 1.25 в координатах 24
геометрия деградирует (окружности перестают быть круглыми при целочисленном
растеризации), поэтому для size > 29 штрих в vb зажимается, фактический вес
становится 1.5–1.8px. Для плиток 32px это даёт 1.67px — допустимая оптическая
надбавка «крупная плитка чуть плотнее».

Единый токен: `E_ICON = 1.5`. Меняется в одном месте, вся таблица выше — производная.

## 3. Карта состояний и анимаций

Общие кривые: `apple = cubic-bezier(.25,.1,.25,1)` (уже в DESIGN.md); все
числовые переходы — `NumberAnimation` c `Easing.BezierSpline [0.25,0.1,0.25,1,1,1]`.
Правило монохрома: анимируется **тон/инверсия/геометрия**, никогда — оттенок.

### 3.1 Панель (контейнер) — открытие/закрытие

| Состояние | Что меняется | Длительность/кривая | Информация пользователю |
|---|---|---|---|
| closed → opening | opacity 0→1, scale .97→1; контент `contentOpacity` стартует на 430-м мс (fade 220ms) | 420ms apple | панель «материализуется» прежде чем оживает: данные не выпрыгивают |
| ghost-эхо | 2 контурных Rect 1px, scale .99→.952, opacity .45→0, задержки +40/+140ms | 380ms apple | «шлейф материализации», только на открытие |
| hover (над панелью) | ничего | — | панели не интерактивны целиком — нет ложного аффорданса |
| closing | зеркало открытия: контент гаснет сразу (120ms), панель 420ms | 420ms apple | симметричный ритм, «тишина вне фокуса» |

### 3.2 Глич-появление (киберпанк, но монохром)

Накладывается поверх профиля открытия (после 420ms контент уже живой; глитч
длится первые ~200–350ms открытия). Важно: джиттерится **Item внутри
поверхности**, не сама layer-shell поверхность — репозиция окна через композитор
даёт лаг и мерцание тени.

**Вариант A — дешёвый (рекомендован для тостов, бара, повторяющихся событий), ~200ms:**

| Приём | Реализация | Время |
|---|---|---|
| Flicker | opacity панели: 0 → .85 → .4 → 1 → .7 → 1 по ключевым кадрам | 0–180ms |
| X-джиттер | `Item.x`: 0 → −2 → +1.5 → −1 → 0 (3–4 рывка) | 0–160ms |
| Инверсные полосы | 2–3 белых `Rectangle` h 2–4px на случайных y, opacity .25–.5, мигают 2 раза | 60–200ms |
| Срез | один горизонтальный срез панели (clip высотой 8–12px) сдвигается на +6px и возвращается | 80–140ms |

Себестоимость: ~8 прямоугольников + NumberAnimation. GPU-цена вне перехода — **0**.
Ничего не копирует текстуру. Безопасно даже для тостов, всплывающих каждые несколько секунд.

**Вариант B — насыщенный (рекомендован для панелей по хоткею: раз в сессию, 350ms):**

`ShaderEffectSource` (live только на время анимации) → `ShaderEffect` поверх панели:

```glsl
// монохромный глитч: построчный сдвиг + инверсия полос + дрожание плотности
float row   = floor(uv.y * H);                 // H ≈ 90 строк
float rnd   = hash(vec2(row, floor(time*24.)));// дискретные кадры 24fps
float shift = (rnd - .5) * step(.82, rnd) * 14.; // 18% строк рвутся на ±7px
vec2  u2    = uv + vec2(shift / W, 0.);
vec4  c     = texture(src, u2);
// двоение вместо RGB-сплита: две моно-копии, разъехавшиеся по x
float ghost = texture(src, u2 + vec2(2./W,0.)).a;
c.a = max(c.a, ghost * .5);
// инверсия случайных горизонтальных полос (1–3 полосы за кадр)
float band = step(hash(vec2(floor(uv.y*6.), floor(time*24.))), .18);
c.rgb = mix(c.rgb, 1.0 - c.rgb, band * .9);
// глобальный фликер + скан-линия
c.a *= .75 + .25 * hash(vec2(floor(time*24.), 7.));
c.rgb *= 1.0 - .12 * smoothstep(.0,.02,abs(fract(uv.y*H)-.5)); // тонкая скан-сетка
```

Монохромность сохраняется: вместо цветного RGB-сплита — **а-разложение** (двоение
контуров), инверсия полос и flicker, т.е. работаем только яркостью.

Оценка GPU-цены: площадь панели 504×544 ≈ 0.27 Мпикс — фрагментный шейдер на
350ms стоит миллисекунды даже на iGPU; «постоянного демона» нет, т.к. шейдер
живёт только 350ms, затем `ShaderEffectSource.live = false` и эффект скрывается
(иначе — лишний FBO ~1.1 МБ на панель навсегда). Для 10 панелей одновременно —
также безопасно (переходы разнесены по хоткеям).

**Рекомендация:** B для панелей (открываются по явному хоткею, эффект = награда за
вызов), A для тостов и бара (частые/транзиентные — глитч не должен надоедать).

### 3.9 Часы DSEG7 (бар)

- Смена значения — **мгновенная, без кроссфейда**: сегментная индикация не
  интерполируется, «щелчок» табло и есть эстетика.
- Глитч-тик каждую секунду — **нет** (шум убивает «тишину вне фокуса»).
- Микро-жест: при смене **минуты** — один flicker opacity .75 на 60ms. При открытии
  бара — часы появляются с общим глитчем панели (вариант A).
- Мигание двоеточия — нет (DSEG7-таблица и так «живая»).

### 3.10 Спарклайн CPU и сегментированные полосы

- **Спарклайн** (гистограмма, тик 1s): новый столбец появляется с fade-in 200ms,
  сдвиг истории — мгновенный. Анимировать сдвиг всех столбцов — шум + перерисовка
  ради нулевой информации.
- **Сегментированная полоса** (штрих 4 / промежуток 3): при изменении значения
  анимировать **не сегменты**, а клип-маску: два наложенных ряда (нижний — «выкл»
  тоном `ghost`, верхний — белый, обрезан по `width = value%`), `Behavior on width`
  **300ms apple**. Сегменты остаются дискретными и хрустящими, изменение — плавное.
  Скачки >20% за тик — анимация всё равно 300ms (не догоняет — это нормально:
  приборка, а не осциллограф).

## 4. Сетка: 3 колонки (фактическое разрешение)

### 4.1 Исходные данные и решение по scale

`hyprctl monitors`: eDP-1, **1920×1080, scale 1.2** → Quickshell оперирует
логическими координатами **1600×900**. Дизайн ведётся в логических px; сетка
`DESIGN.md` (на 1920 логических) напрямую не помещается — пересчитана.

Два режима работы:
- **A (рекомендован, текущий):** scale 1.2, логическая сцена 1600×900 — таблица ниже.
- **B (если когда-нибудь вернёшь scale 1):** логическая 1920×1080 — коэффициент
  1.2 ко всем размерам (таблица в §4.5).

Предупреждение: при scale 1.2 размер 9px (labels) = 10.8 физических px — читаемо.
При переходе на scale 1 поднимать минимальные кегли до 11px, иначе метки
перестанут читаться.

### 4.2 Внешняя сетка (1600×900, режим A)

```
внешние поля:            24 со всех сторон
зазор между колонками:   20
зазор между зонами (Y):  20
верхняя лента:           y = 24,  высота 288
нижняя зона:             y = 332, высота 544
ширина колонки:          (1600 − 2·24 − 2·20) / 3 = 504
x колонок:               24 · 548 · 1072  (правый край 1576 = 1600−24 ✓)
```

Обоснование высоты верхней ленты: календарь = head 32 + строка недели 18 + сетка
6×32 = 192 + foot 26 + вертикальные паддинги 20 = **288**. Больше ленте давать
нечего (бар и тосты транзиентные), а каждый px сверху — минус у нижних панелей,
которым и так тесно.

### 4.6 Адаптивная формула (другие мониторы)

```
M = 24; G = 20 (если W/3 даёт остаток при G=24, иначе G = 24)
colW = floor((W − 2M − 2G) / 3)
topH = 32 + 18 + 6·cell + 26 + 20,  cell = 32..38 (подбор под высоту)
botY = M + topH + 20;  botH = H − botY − 24
2-панельная колонка:  h = (botH − 20) / 2
3-панельная колонка:  chat ≥ 240, aimgr ≥ 140, notif ≥ 108 (минимумы каркаса)
центр:                sysinfo = botH − 20 − logout,  logout = 176
```

78% тела 346px, таблица taskmgr сжимает name). Ниже — панели переходят в
одну колонку 2×N (вне скоупа текущей сцены).

## 5. Итоговые решения (коротко)

1. **Иконки — Lucide** (ISC, 2015 глифов, единая сетка 24/2). Брать
   `lucide-static` → `icon-nodes.json` (один JSON → `Icon.qml`), офлайн; имена
   актуализировать (`triangle-alert`, `trash`, `ellipsis`, `funnel`).
2. **Effective stroke = 1.5px** везде; `stroke_vb = 36/size` (пол 1.25). Токен
   `E_ICON` один на весь UI.
3. **Глитч**: ShaderEffect (вариант B, 350ms, построчный сдвиг + моно-двоение +
   инверсия полос + flicker) для панелей по хоткею; дешёвый flicker+jitter (A,
   200ms) для тостов и бара. Постоянная GPU-цена — ноль, шейдер живёт только
   во время перехода.
4. **Сетка**: реальная сцена 1600×900 (scale 1.2!). Колонки 504px на x = 24 / 548 /
   1072, верхняя лента 288, нижняя зона 544 (y 332). Панели: docker/taskmgr 504×262,
   sysinfo 504×348, logout 504×176, chat 504×244, aimgr 504×148, notifcenter 504×112,
   launcher 504×48 (+список 504×348), calendar 264×288, toasts 276.
5. Точки: пульс только у filled, 2s; DSEG7 — без глитч-тика каждую секунду, микро-flicker
   на смене минуты; сегментные полосы — плавный клип 300ms, сегменты дискретны.
