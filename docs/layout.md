# Layout: слоты, окна, маски, IPC

## Сетка

Сетка рассчитывается от фактического логического экрана `Quickshell.screens[0]`
(базовый дизайн — 1600×900 при monitor scale 1.2). Позиции/отступы окон вычисляются
в shell.qml от реального `width/height`; дизайн-размеры (шрифты, высоты хрома,
габариты слота) умножаются на `Theme.px`:

```
px  = screenScale / 1.2                      (Theme.f(base) = Math.round(base·px))
pad = round(W·24/1600)                       — базовый отступ 24
slotW×slotH = round(504·px) × round(544·px)
слот A: x=pad   слот B: x=(W−slotW)/2   слот C: x=W−pad−slotW   y=H−slotH−pad
```

На базовом 1600×900@1.2 (px=1) формулы воспроизводят старые числа: pad=24,
B=(1600−504)/2=548, C=1600−24−504=1072, y=900−544−24=332. На scale 1.25 экран
логически уже, но позиции и px-габариты следуют за ним — панели помещаются
и становятся пропорционально крупнее (как остальной текст Wayland).

```
верхняя лента, y=pad:   calendar (x=pad)   bar (центр, окно wBar=360·px ≈ 375)   toasts (право)
(календарь по умолчанию скрыт — виден по SUPER+C / toggleCalendar, при показе развёрнут;
 свертывание в чип остаётся живым состоянием на время показа)
нижний ряд,  y=H−544·px−pad:    СЛОТ A (x=pad)   (СЛОТ B — см. ниже, центр)   СЛОТ C (право)
```

### Слот B — компактное окно (Task 24)

Окно слота B НЕ фиксированной высоты `slotH`: его высота следует контенту,
нижняя кромка всегда приклеена к `y = H − pad` (margins.top читает
анимируемую implicitHeight — рост/усадка одной кривой `Motion.launcherGrow`).

| Состояние | Высота окна |
|---|---|
| launcher стадия 1 (dock без запроса) | `hDock` = 48·px ≈ 50 |
| launcher стадия 2 (есть запрос/стрелки) | `hSlotB` = hDock + 4·hRowL ≈ 190 |
| logout | hHead + 12 + 2·hTile + s6 + 16 + hFoot ≈ 241 |

Высоту ведёт `LayoutState.launcherStage2` (volatile, пишется Launcher.qml);
shell.qml собирает её в `colBH` и анимирует окно. Grab и маска при усадке
не ломаются: focus-grab и `mask: Region` привязаны к самому окну, не к slotH.

Компоновка бара (пункт №8, components/StatusBar.qml): слева — только часы
DSEG7 (HH:mm, без даты/дня недели), по центру — воркспейсы (базово 4;
занятые 5–6 добавляются по occupied-детекту `Hyprland.workspaces`),
справа — раскладка. Клик воркспейса — `HyprlandWorkspace.activate()`
(документированный путь Quickshell 0.3.2; прежний `dispatch("workspace N")`
падал на lua-эре Hyprland 0.57, гонка 250ms убрана).

ОСД в баре (пункт №9): внутренние режимы volume/brightness — тот же контейнер
360×44 (Task 24: было 500×44), окно/маска не переоткрываются; слои barLayer/osdLayer друг над другом,
кросс-fade `Motion.osdSwap`. Громкость — push из Pipewire
(`PwObjectTracker` на defaultAudioSink, ловит любые источники), яркость — IPC
`archui osd brightness` из биндов яркости + sysfs-поллинг значения (300ms, только
пока режим активен). Смена воркспейса/раскладки возвращает обычный контент.

Все окна — `PanelWindow` на layer top, `exclusionMode: Ignore` (место у тайлов
не отъедают), создаются один раз при старте демона и живут всегда.

Назначение слотов (panelId → слот):

| Слот | Панели |
|---|---|
| A | `docker`, `taskmgr`, `sysinfo` |
| B | `launcher`, `logout` |
| C | `chat`, `aimgr`, `notifcenter` |

## Открытие / замена / закрытие

`toggle(panelId)` (services/LayoutState.qml):

- слот показывает эту же панель → **закрытие** (зеркальная хореография);
- слот пуст → **открытие**: панель 420ms (opacity 0→1, scale .97→1, кривая
  apple), контент — fade 220ms с задержкой 140ms, ghost-эхо + глич;
- слот показывает другую панель → **замена**: старая уходит 180ms
  (fade + scale .97, **без ghost-эхо**), новая стартует на +120ms **выше по z**
  (стек Loader'ов, клип по слоту).

Хореографию делает kit/Panel.qml — панели-компоненты её не повторяют.

## Клик «+N critical» заменяет занятый слот C

Critical-уведомления сверх стека тостов сворачиваются в счётчик «+N critical»
(см. notifications.md). Клик по нему открывает NotifCenter. Если слот C занят
другой панелью (например, чатом) — NotifCenter **заменяет** её на месте
(требование «второй замещает первый»). Чат-процесс pi при этом **не убивается**:
он следит за слотом C и живёт, пока не появится снова (см. agent-chat.md).

## KeyboardFocus

Семантика hyprland-focus-grab-v1 (Task 26, сверено с quickshell
src/wayland/hyprland/focus_grab и Hyprland 0.57 src/protocols/FocusGrab.cpp,
src/desktop/state/FocusState.cpp, src/managers/SeatManager.cpp): активный grab —
это CSeatGrab по pointer И клавиатуре разом, `m_keyboard = true` захардкожен
композитором (FocusGrab.cpp:20), у протокола v1 нет флага клавиатуры, у qs
`HyprlandFocusGrab` — только `active`/`windows`. Пока grab жив, композитор
ОТКАЗЫВАЕТ отдавать wl_keyboard любой поверхности вне whitelist
(FocusState.cpp:238 «surface … won't receive kb focus because grab rejected
it»): activate по foreign-toplevel выполняет «окружение» фокуса (activewindow-
события постятся), но клавиатуру молча оставляет панели. Поэтому «grab жив +
ввод у тайла» протоколом не достигается ВООБЩЕ — фиксы Task 21 (возврат
фокуса через foreign-activate) нельзя было спасти никаким таймингом.

Решение (F1, выбор юзера 2026-11-03; shell.qml):

- **dismiss-grab держат ТОЛЬКО панели с текстовым вводом**: taskmgr (фильтр)
  и chat (поле ввода). Клавиатура при активации grab уходит панели — ей она и
  нужна. Лаунчер держит собственный grab (см. ниже).
- **пассивные панели** (sysinfo/docker/notifcenter/aimgr/logout/calendar/bar)
  **grab не активируют вообще** → их открытие никогда не трогает клавиатуру
  тайла (`CFocusGrab::refocusKeyboard` не зовётся — клавиатура остаётся окну).
- Плата (осознанный trade-off юзера): клик мимо пассивной панели её больше
  НЕ закрывает. Закрытие: повтор того же бинда (`toggle` идемпотентен) или
  замена другой панелью.
- launcher — `Exclusive` при открытии + собственный `HyprlandFocusGrab`
  ([colB]); dismiss-grab при открытом лаунчере гасится (у Hyprland один grab
  на seat — `CSeatManager::setGrab` замещает прежний и зовёт его callback →
  `finish(true) → cleared`): иначе onCleared dismiss-grab'а ложно срабатывал
  как «клик мимо» при КАЖДОМ открытии лаунчера поверх панели (pre-existing
  каскад из ведомости, живой лог 2026-11-03). Пока лаунчер открыт,
  панели-с-текстом живут, но теряют click-outside dismissal до его закрытия.
- слот-окна — `OnDemand`: клавиатура у панели только после клика в неё
  (текстовое поле получает её кликом; Esc-обработка kit/Panel от grab
  не зависит);
- при закрытии слота фокус-режим возвращается в `OnDemand` (не `None`) — окно
  скрыто и маска пуста, практической разницы нет; зафиксировано как осознанное
  решение.

## Маски ввода

Никогда не полагаемся на ввод «по геометрии»: у каждого окна `mask: Region`,

- слот закрыт / бар скрыт / тостов нет → **пустая маска** (окно прозрачно для
  кликов — тайлы под ним кликаются);
- панель открыта → прямоугольник панели, переключается в той же хореографии,
  что и visible.

Симптом «клики под панелью не проходят / панель не кликается» — это маска,
смотри kit/Panel.qml, а не компонент панели.

## Жизнь панелей

После первого открытия инстанс панели живёт всегда (`Loader.active` не
гасится — деактивация уничтожила бы состояние: открытый таб, фильтр, историю
ленты). «Спят» только тяжёлые вещи: поллинг сервисов и анимации биндятся на
видимость панели (подробнее — services.md).

## Overlay-механика

kit/Panel.qml принимает `overlay: Component` — контент на всё окно слота без
head/foot/pad/clip (Loader поверх всего слота, z:3, едет в общей волне
открытия). Так лаунчер кладёт dock у нижней кромки окна и список до 4 строк
(hRowL), растущий от dock вверх; стадия 1 — только dock без пустого стекла
над ним (Task 24; было: список 504×372 в фиксированном окне slotH). При замене/закрытии демонтаж overlay-Loader'а
отложен до конца уход-анимации (replaceExit/panelOpen) — дырки в переходе нет.

## IPC и хоткеи

См. [README.md](README.md). Хоткеи и window/layer-рулы — в
`~/.config/hypr/hyprland.lua` (вне репо): namespaces окон `archui:*`
(`archui:col-a/b/c`, `archui:calendar`, `archui:bar`, `archui:toasts`), blur-рулы
по ним же.

## Состояние при reload/рестарте

Открытые слоты, бар и DND персистятся (`PersistentProperties`, reloadableId
«layout») — после рестарта демона панели восстанавливаются. Но remember:
изменения в **синглтонах** проверять полным рестартом — hot-reload не всегда
поднимает новый инстанс синглтона.
